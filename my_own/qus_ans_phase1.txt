Q5 Function Calling ke complete cycle mein 5 steps hote hain. Inko aasan Roman Urdu mein tarteeb se batayein: (Hint: User Query -> Model tool decision -> Python execution -> Tool output to Model -> Final user reply)
5 steps bilkul asan Roman Urdu mein yeh hain:
1. User Query (Sawal Bhejna). User apna sawal poochta hai, aur aap ki app us sawal ke saath maujooda tools ki list (Menu) AI model ko bhejti hai.
2. Model Tool Decision (AI ka Faisla). AI sawal parh kar tay karta hai ke usay kisi tool ki zaroorat hai, aur jawab dene ke bajaye aap ki app ko ek JSON parchi (function_name aur arguments) likh kar deta hai.
3. Python Execution (Asli Kaam Karna). Aap ka Python code us JSON parchi ko parh kar asli function chalata hai aur database ya API se live data nikalta hai.
4. Tool Output to Model (Result Wapas Dena). Aap ki app woh nikala hua data (result) wapas AI model ko bhejti hai taake AI ko asli haqeeqat pata chal jaye.
5. Final User Reply (Aakhri Jawab). AI us sukhe hue data ko parh kar ek pyare aur aam insaani jumle mein badal kar user ko final jawab suna deta hai.

Q1. Groq ka LPU (Language Processing Unit) traditional Nvidia GPUs ke muqablay mein itna fast (500+ tokens/sec) kyun hai? Iske hardware design mein ahem farq kya hai
Groq ka LPU (Language Processing Unit) traditional Nvidia GPUs ke muqablay mein is liye itna fast hai kyunkay yeh sirf AI inference (sequential processing) ke liye banaya gaya hai aur is mein external memory (HBM) ki jagah ultra-fast on-chip SRAM istemal hoti hai.


Q2. Streaming (stream=True) ka technical matlab kya hai? Aur ek Flutter mobile ya Next.js web application mein streaming use karne se User Experience (UX) par kya farq parta hai
stream=True ka matlab hai ke server poora response mukammal hone ka intezar karne ke bajaye Server-Sent Events (SSE) ke zariye har naya generate hone wala token (lafz ka tukda) foran client ko bhejta rehta hai

Q3. Synchronous (Groq) aur Asynchronous (AsyncGroq) calls mein kya farq hai? Ek customer support SaaS platform mein jahan 500 users aik hi waqt mein bot se baat kar rahe hon, wahan Async kyun lazmi ho jata hai?
Synchronous (Groq) calls mein server ek user ka AI response aane tak ruk (block) jata hai aur baqi sab ko line mein khada rakhta hai, jabke Asynchronous (AsyncGroq) calls mein server bina ruke hazaron requests ko ek saath (parallel) handle karta hai

Q4. Agar aapki production application ko Groq se RateLimitError (429) milna shuru ho jaye, toh Exponential Backoff strategy kya hoti hai aur yeh app ko crash hone se kaise bachati hai?
Exponential Backoff aik aisi smart retry strategy hai jis mein error aane par app foran dobara request bhejne ke bajaye har koshish ke baad intezar ka waqt (delay) dugna karti jati hai—jaise pehle 1 second, phir 2 seconds, phir 4 seconds, aur phir 8 seconds.

Q5. Python terminal mein streaming response print karte waqt print(chunk, end="", flush=True) mein flush=True lagana kyun zaroori hota hai?
Python ke print() function mein flush=True lagana is liye zaroori hota hai taake har naya lafz (chunk) foran terminal screen par nazar aaye, na ke Python ke internal memory buffer mein jama ho kar line poori hone ka intezar kare.

Q1
Ek Hospital ya Bank ka client Cloud AI (OpenAI/Groq) ke bajaye Local AI (Ollama) par insist kyun karta hai? Asal technical aur legal wajah kya hoti hai?

Ek Hospital ya Bank ka client Cloud AI (OpenAI/Groq) ke bajaye Local AI (Ollama) par is liye insist karta hai kyunke un ke paas mareezon aur customers ka intehayi hassas (sensitive) data hota hai, jise woh kisi teesri company ke external servers par bhej kar data leak hone ya qanooni (legal) karwai ka risk nahi le sakte

Q2. Model Quantization Kya Hoti Hai? (16-bit se 4-bit Compress Karna)

• Asan Matlab: Quantization ek aisi technique hai jis mein AI model ke andar ke bade decimal numbers (16-bit ya 32-bit weights) ko chota karke 4-bit (Q4) mein compress kiya jata hai, taake model ki file ka size chota ho jaye.
• Faida: Is se 60% se 75% tak kam RAM/VRAM lagti hai aur model aam laptops par bhi tez chalta hai, jabke us ki aqal (intelligence) par sirf 1% se 2% ka mamooli farq padta hai.

Q3. VRAM (GPU Memory) vs System RAM (Computer ki Aam RAM)

• VRAM (Graphics Card ki Memory): Yeh GPU ke bilkul upar lagi hoti hai aur bohat super-fast (high bandwidth) hoti hai. Jab AI model poora VRAM mein fit ho jaye, to woh bijli ki tezi (30 se 80+ tokens/sec) se jawab deta hai.
• System RAM (Aam RAM): Yeh CPU ke saath kaam karti hai aur VRAM ke muqable mein bohat slow hoti hai. Agar GPU na ho aur model System RAM par chale, to speed bohat kam (3 se 10 tokens/sec) ho jati hai aur laptop ka pankha tez chalne lagta hai.

Q4. 8GB ya 16GB Normal Laptop (Bina Heavy GPU) par Kaunsa Model Chalayein?

• Mashwara: Aise laptop par hamesha 1B ya 3B (aur zyada se zyada 7B/8B Q4 agar 16GB RAM ho) model chalane ka mashwara dena chahiye.
• Wajah:
	• 70B model ko ~45GB+ RAM chahiye hoti hai, is liye woh crash ho jayega.
	• 8GB RAM wale laptop mein Windows khud 3-4GB RAM le leti hai, to peeche bachi 4GB RAM mein sirf 1B ya 3B model hi makhan ki tarah chal sakta hai.

Q5. Ollama ka Local Port aur OpenAI SDK Connection

• Local Port: Ollama background mein default taur par port 11434 par local web server chalata hai (http://localhost:11434).
• OpenAI SDK Connection: Jee haan, 100%! Ollama OpenAI-compatible API (http://localhost:11434/v1) deta hai. Aap ko apne OpenAI Python ya JavaScript code mein sirf base_url ko change karke http://localhost:11434/v1 karna hota hai, aur aap ka purana code seedha local Ollama model ke saath chalne lagta hai

Q1. AI Pricing Standard Unit

• Jawab: AI industry mein tamam cloud providers (Groq, OpenAI, Anthropic) apni pricing Per 1 Million (1,000,000) Tokens ke standard unit mein quote karte hain.

Q2. Output Tokens 3x se 4x Mehenge Kyun Hote Hain?

• Jawab: Input Tokens ko GPU ek hi waqt mein (parallel) parh leta hai, jabke Output Tokens ko AI ek-ek token karke (sequentially) banata hai aur har naye token ke liye poore purane text par dobara heavy calculations karta hai—jis se GPU memory aur waqt zyada kharch hota hai.

Q3. Prompt Caching Kya Hai aur API Cost par Asar?

• Jawab: Prompt Caching mein server aap ke baar-baar use hone wale bade System Prompt (2,000 tokens) ko apni temporary memory mein save kar leta hai, jis se har agle customer ki request par us hissay ka bill 75% se 90% tak kam ho jata hai.

Q4. $5 Subscription vs $12 Bill (Nuqsan se Bachne ke 2 Mashwaray)

1. Model Routing (Sasta Model Use Karein): Aam sawalon ke liye mehenge OpenAI model ke bajaye Llama 3.1 8B (Groq) par shift hon, jis se API bill $12 se gir kar $0.20 par aa jayega.
2. The Rule of 3x–5x aur Message Limits: Har user par mahana message limit lagayein (taake koi abuse na kare) aur apni kul cost (COGS) ko 3x se 4x se zarb de kar subscription price set karein taake 70%+ profit margin bache.

Q5. Unexpected $5,000 Bill se Bachne ke 2 Safety Controls

1. Hard Spend Limits (Provider Dashboard): OpenAI ya Groq ke dashboard mein monthly Hard Spending Cap (jaise $50) lagayein taake is limit ke baad API khud ruk jaye aur card charge na ho.
2. User Rate Limiting & max_tokens Guard: Backend mein har user ke liye ghante/din ki message limit set karein aur har API call mein strict max_tokens lagayein taake AI kabhi be-lagam lamba jawab na likhe.

modeul 9

1. Context Sliding Window Algorithm Kya Hai aur 50 Messages par Asar?

• Jawab: Sliding Window ek aisi technique hai jis mein hum poori lambi chat bhejne ke bajaye sirf System Prompt + aakhri N (jaise 6) recent messages AI ko bhejte hain aur purane messages kaat dete hain.
• Bina Sliding Window ke Asar: 50 messages tak har naye sawal par pichle saare messages baar-baar read hone ki wajah se API bill bohat zyada barh jayega aur model ki memory limit (Context Window) bhar kar system Crash (context_length_exceeded) ho jayega.

Q2. System Prompt (history[0]) ko Bacha Kar Rakhna Kyun Ahem Hai?

• Jawab: System Prompt mein AI ka buniyadi kirdar (persona) aur company ke rules (Guardrails) likhe hote hain. Agar sliding window mein ghalti se history[0] drop ho jaye, to AI apni pehchan aur pabandiyan bhool kar ek aam, be-lagam chatbot ban jayega aur ghalat discounts ya un-professional jawabat dena shuru kar dega.

Q3. Session State Management (Session IDs) Kyun Lazmi Hai?

• Jawab: Multi-user app mein har customer ki baat-cheet ko alag aur mehfooz rakhne ke liye Session IDs lazmi hain. Agar hum aik hi global list chat_history = [] use karein, to Customer A aur Customer B ki baatein aapas mein mix ho jayengi, jis se Customer A ki private maloomat (jaise order details ya bank info) Customer B ko nazar aane lagenge (Critical Data Privacy Leak).

Q4. Structured Log (JSONL File) mein Save Karne ke 2 Faiday

1. Audit Trail & Dispute Resolution. Agar koi customer shikayat kare ke bot ne ghalat qeemat ya ghalat mashwara diya tha, to log file se asli baat-cheet ka saboot mil jata hai.
2. Analytics & Fine-Tuning. Is data se mahine ke kharchay ka hisab lagaya ja sakta hai aur future mein apne AI model ko mazeed behtar train (fine-tune) karne ke liye asli sawal-jawab mil jate hain.

Q5. Tokens aur Kharchay ko Live Track Karne ko Kya Kehte Hain?

• Software Engineering Term: Is process ko Telemetry (ya Usage & Cost Metering / Observability) kehte hain.
• Business Faida: Is se SaaS owner ko har customer par aane wali asli cost (Unit Economics) ka live pata chalta rehta hai, jis se woh sahi subscription price tay kar sakta hai aur nuksan se bach kar munafa (Profit Margin) mehfooz rakhta hai.

module 10


Q1. Traditional Software Testing vs AI / LLM Testing ka Farq

• Fundamental Farq: Traditional software Deterministic hota hai (har baar bilkul wahi ek jawab aata hai), jabke AI / LLM Non-Deterministic hota hai (har baar thode badle hue alfaaz mein jawab deta hai).
• Exact String Match Kyun Fail Hoga? Kyunke AI kabhi kahega "Delivery charges Rs 200 hain" aur kabhi kahega "Rs 200 flat delivery fees lagegi"—baat dono mein sahi hai, lekin alfaaz exact match na hone ki wajah se assert response == "..." fail ho jayega.

Q2. Semantic Assertions: Inclusion vs Negative Constraint

• Inclusion (Must-Contain): Yeh check karna ke jawab mein zaroori haqeeqat (fact ya number) lazmi maujood ho—chahe jumla kuch bhi ho.
	• E-Commerce Misal: assert "200" in response (Delivery charges batate waqt 200 ka lafz lazmi hona chahiye).
• Negative Constraint (Must-NOT-Contain): Yeh check karna ke AI ne koi rule tod kar ghalat ya khufiya baat to nahi bol di.
	• E-Commerce Misal: assert "50%" not in response (Customer ke maangne par bhi 50% discount ka zikr nahi hona chahiye).

Q3. Prompt Regression Kya Hai aur Isay Kaise Check Karte Hain?

• Prompt Regression: Jab aap System Prompt mein kisi ek cheez ko behtar karne ke liye tabdeeli karein aur us ke nateejay mein bot ke purane sahi rules ya guardrails toot jayein (jaise friendly banne ke chakkar mein zyada discount de dena).
• Hal: Yeh check karne ke liye ke purani policies mehfooz hain ya nahi, hum Automated Regression Testing (pytest + Golden Test Dataset) run karte hain.

Q4. Testing ke Waqt Temperature = 0.0 Kyun Set Karte Hain?

• Wajah: Temperature = 0.0 set karne se AI bilkul sanjeeda aur consistent (Deterministic) ho jata hai aur har baar sab se pakka jawab deta hai, jis se hum asli ghalti ko pakad sakte hain.
• Temperature = 1.0 Chhorne ka Masla: Agar 1.0 rakhein ge to AI har test run mein naye tukkay aur creativity lagayega, jis se kabhi test pass hoga aur kabhi fail (Flaky Tests), aur aap ko asli maslay ka pata nahi chalega.

Q5. Golden Test Dataset Kya Hai aur CI/CD (GitHub Actions) mein Pytest ka Commercial Faida?

• Golden Test Dataset: Yeh 15 se 20 mushkil aur ahem business scenarios (jaise pricing, return policy, aur prompt injection attacks) ka ek fixed benchmark set hota hai jis par har bot ka imtehan liya jata hai.
• Commercial Faida: GitHub Actions (CI/CD) mein pytest lagane se har naye code ya prompt update se pehle yeh tests khud-ba-khud chalte hain; agar aik bhi policy toot rahi ho to system deployment ko automatically block kar deta hai—jis se company lakhon rupay ke ghalat discounts, data leaks, aur client nuqsan se bach jati hai.
